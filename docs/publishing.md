# 明确发布文章

博客仓库和 Issue 都是公开的。文章写入 Issue 或 Note 评论时不会自动进入网站；只有手动运行 **Publish an article** 工作流后才会更新博客。

## 发布 Blog Issue

1. 在博客仓库创建或编辑 Issue，并添加配置中的 Blog 标签。
2. 打开 Actions → **Publish an article**，将该 Issue 的地址粘贴到 `source_url`，然后运行。
3. 工作流会冻结 Issue 正文、检查主题内容并部署同一份文章快照。Issue 的评论不会自动拼接到文章中。

## 发布 Note

1. 在初始化任务创建的 Note 容器中写一条评论。
2. 从评论菜单复制该评论的永久链接。链接需要包含 `#issuecomment-ID`。
3. 在 **Publish an article** 中粘贴此链接并运行。

Note 可以用 HTML 注释提供可选标题、摘要和标签；这些标记不会显示在文章正文中：

```markdown
<!-- title: 一条简短的标题 -->
<!-- description: 一句摘要 -->
<!-- tags: 随笔, 生活 -->

正文从这里开始。
```

如果省略标题，工作流会从正文标题或首句生成标题。标签按逗号分隔，也可以每行写一个 `- 标签`。

## 快照、地址与重试

每次手动发布都会重新读取源稿并保存到 `.blog/content/posts/`，同时在 `.blog/receipts/` 保存来源、版本摘要和文章地址。修改 Issue 或评论不会自动改变线上版本；再次明确发布才会更新它。

同一个 Issue 使用 `blog-<Issue 编号>` 地址，同一条 Note 使用 `note-<评论编号>` 地址。改标题和重复发布都保留地址。Windows 可检出的文章文件名由来源类型和数字标识组成，不依赖标题或时间戳。

工作流在一次任务中准备内容、运行 Astro 校验与站点部署，不依赖 `GITHUB_TOKEN` 产生的 push 再触发另一个工作流。重复发布已成功部署的同一快照不会重复部署；如果部署失败，任务不会记录为成功，重新运行同一来源链接会继续尝试部署。

任务日志只输出来源链接、快照标识和结果，不打印完整文章正文。公开 Issue 和评论仍然可以被仓库访问者阅读，不能当作私密草稿。

仓库内的 `.agents/skills/blogkit-publish/SKILL.md` 为兼容的 AI 助手提供同一发布流程，不包含个人仓库或默认 Issue。
